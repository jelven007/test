# 文档基线

本文档集定义“一进二”策略研究与当日实盘系统的当前实现、业务约束、架构、
数据契约、接口、质量门槛和后续生产验证要求。

## 文档状态

- 基线版本：`2.2`
- 基线日期：`2026-10-04`
- 当前实现：Python 多服务运行时 + Kafka + Flink + PostgreSQL + ClickHouse + Redis + MinIO
- 部署形态：火山引擎 VKE 生产环境已上线，本地 Compose 用于开发和集成验证
- 数据源：仅使用 `mootdx`
- 系统边界：研究、筛选、监控和报告，不连接券商，不自动下单

文档中的状态标记：

- `CURRENT`：仓库当前已经具备并可运行的能力。
- `TARGET`：生产化迭代必须实现的目标能力。
- `DEFERRED`：已识别但不进入近期迭代的能力。

## 规范优先级

发生冲突时按以下顺序处理：

1. 需求规格中的硬性业务规则和验收条件。
2. OpenAPI、AsyncAPI 及数据唯一性约束。
3. 系统架构中的组件职责和可靠性语义。
4. 测试、部署和迭代文档。
5. 根目录 `README.md` 中的使用说明。

任何改变策略规则、存储归属、API 字段或事件 Schema 的修改，必须同时更新对应文档和
自动化测试。目标接口在实现前不得标记为 `CURRENT`。

## 当前实现

- 生产入口为 <https://shanao.asia>，由火山引擎 ALB 终止 HTTPS 并转发到 VKE API。
- VKE 当前采用应用多副本、数据服务单副本 StatefulSet 的成本优先拓扑；EBS 保存数据和
  采集 WAL，NAS 提供共享报告目录。完整现状见
  [当前生产技术方案](13-current-production-solution.md)。
- 行情由 `market-collector` 通过 mootdx 长连接采集，并经 SQLite WAL 可靠发布到 Kafka。
- Flink 计算实时特征；`market-sink`、`strategy-engine`、`outbox-relay` 和
  `projection-worker` 分别负责行情、状态、事件和 Redis 投影。
- FastAPI 提供 `/api/v1`、SSE、健康检查、Prometheus 指标和四个 Web 页面。
- `market-reference-sync` 每个工作日 16:20 将证券目录、四类板块文件和行业配置先归档
  到 MinIO，再事务发布到 PostgreSQL；股票目录和板块 API 读取已发布快照。
- PostgreSQL 保存证券和板块时点版本、可重命名且参数不可变的策略目录，以及策略运行、
  计划、逐日记录和研究元数据。
- MinIO 保存原始主数据、版本化报告和研究归档，ClickHouse 保存行情与分钟线，Redis
  保存可重建实时投影。
- 报告调度在 `16:30`、`23:30` 运行，重启后检查最近 7 天遗漏时点并补跑。
- 涨停历史在工作日 `16:35` 增量同步，模拟盘在 `16:50` 按冻结规则生成前向样本。
- 已完成一年期 242 个交易日的双策略计划与实际行情回填，并保留独立研究候选。
