# 生产化文档基线

本文档集定义“一进二”策略研究系统从本地原型演进为真实线上系统的需求、架构、
数据契约、接口、质量门槛和迭代顺序。

## 文档状态

- 基线版本：`1.0`
- 基线日期：`2026-09-24`
- 当前实现：Python 单进程本地原型
- 目标实现：Kafka + Flink + PostgreSQL + ClickHouse + Redis + S3/MinIO
- 数据源：仅使用 `mootdx`
- 系统边界：研究、筛选、监控和报告，不连接券商，不自动下单

文档中的状态标记：

- `CURRENT`：仓库当前已经具备并可运行的能力。
- `TARGET`：生产化迭代必须实现的目标能力。
- `DEFERRED`：已识别但不进入近期迭代的能力。

## 规范优先级

发生冲突时按以下顺序处理：

1. 需求规格中的硬性业务规则和验收条件。
2. OpenAPI、AsyncAPI 及数据唯一性约束。
3. 系统架构中的组件职责和可靠性语义。
4. 测试、部署和迭代文档。
5. 根目录 `README.md` 中的使用说明。

任何改变策略规则、存储归属、API 字段或事件 Schema 的修改，必须同时更新对应文档和
自动化测试。目标接口在实现前不得标记为 `CURRENT`。

## 当前与目标差距

| 领域 | CURRENT | TARGET |
| --- | --- | --- |
| 行情采集 | 进程内线程、mootdx 长连接 | 独立采集服务、分片租约、本地 WAL、自动切源 |
| 数据总线 | 无 | Kafka，按股票有序、可重放、带 DLQ |
| 实时计算 | Python 内存计算 | Flink 窗口指标和板块强度计算 |
| 策略状态 | 内存，重启丢失 | PostgreSQL 持久状态机和审计事件 |
| 高频历史 | JSONL 文件 | ClickHouse 热数据和 S3/MinIO 冷归档 |
| 实时查询 | 进程内缓存 | Redis 投影缓存，权威存储回源 |
| HTTP 服务 | ThreadingHTTPServer、`/api/*` | 多副本 API、`/api/v1/*`、鉴权和可观测性 |
| 报告 | 本地 Markdown/CSV/JSON | PostgreSQL 元数据 + S3/MinIO 版本化对象 |
| 运维 | launchd、本机运行 | 容器化、多可用区、监控告警、备份恢复 |

## 进入迭代的门槛

开始生产化代码改造前，应满足：

- 本文档集通过评审并作为迭代基线。
- 近期范围保持为“动态候选池实时监控”，不承诺全市场逐笔行情。
- 生产组件版本、部署环境和资源预算已确定。
- OpenAPI、AsyncAPI 和核心数据唯一键不再存在未决项。
- 第一阶段的验收测试能够在 CI 中自动执行。
