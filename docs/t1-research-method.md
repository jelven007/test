# 涨停后隔日交易研究的复现方法

本研究只读取 mootdx 及其 PostgreSQL 历史快照，不接券商、不下单。收益标签、规则选择和图表导出与生产筛选器分离。

## 数据与固定口径

机器可读协议见 [2026 年研究协议](research/2026-limit-up-protocol.json)。协议在收益回放前固定。分笔探测发现首分钟成交量包含开盘集合竞价后，收益回放前将协议升级为 v2，排除了该分钟的卖出成交判断。

首轮回放后，v3 修正科创板至少 200 股的市场申报要求，保留 100 股递增的保守数量选择。主板参数与规则网格均未变化；原 v2 选择及结果已归档，重新计算后逐项核对主板 R0381 的各阶段统计完全一致。该修正不是根据留出收益重新调参。

- D1 是收盘涨停日，D2、D3 是后续两个**市场交易日**。股票停牌不能把 D3 顺延。
- 默认排除价格恰好涨 5% 但历史 ST 状态未核实的记录。主策略使用沪深主板、D1 首板、D1 成交额不低于 2 亿元。
- 每只股票每种入场规则独立假设 1 万元预算，按 100 股递增，科创板额外要求至少 200 股，委托数量按事前限价计算。实际投入通常小于预算，收益分母为实际买入现金含费用。
- 买入限价不超过 D1 收盘价的 109%，也不接受涨停价成交。观察到价格跌破 D1 收盘价即取消当日尚未成交的委托。
- 三种固定买点为首分钟后挂单、突破开盘及首分钟价格、回落后重新越过开盘价。每次都先观察信号，至少下一分钟才判断成交，最后允许的分钟结束时间为 09:59。
- 历史分时只有价格采样和成交量，不是分钟 OHLC。240 个样本按分钟结束时间编号；例如 09:32 表示 09:31 这一分钟的数据。原始分笔只有分钟时间标签，不能据此声称精确秒级成交。
- 每笔委托股数必须不超过被观察分钟成交股数的 1%。这是容量假设，不是盘口撮合证明。
- 双边佣金为万分之三、单边最低 5 元；双边过户费为十万分之一；卖出印花税万分之五；买卖各计 0.1% 滑点并按分取整。账户实际费率不在数据中。

三种退出口径分别为 D3 日线开盘基准、首分钟后发单并等待首个可成交分钟、事先计算净收益至少 5.1% 的限价止盈。开盘基准仅用于比较，没有集合竞价排队证明。止盈模型须观察到高于滑点调整后止盈价至少一分钱的价格和足够成交量，成交记预定止盈价；未触发则在 14:55 提交退出，使用 14:56—14:57 分钟结束的证据。第三天跌停、容量不足、停牌或缺数据导致不能确认退出的，保留在已买入事件的成功率分母中。

**“收益超过 5%”不同于“赚钱”“盘中最高价曾超过 5%”或“第二天封板”。** 后三项不能替代本次目标。

## 数据核验及不确定性

每个分时日检查 240 条完整性、价格/成交量有效性、末笔价格与日线收盘的匹配、所有采样价在日线高低区间内、分时成交量合计与日线成交量偏差不超过 2%。全日信息只用于数据一致性检查，不能用于回头取消已经发生的买入。

有除权、缩股或拆股影响 D2/D3 的事件另行标记；本版本不推算股息到账、送股交付及持有期税费。D3 发生此类变化的已买入样本仍保留在保守成功率分母。没有 D2 日线只代表该市场交易日缺少个股日线，不武断等同为已经核实的停牌。

名称、行业、ST 状态不是完整历史版本。行业只做描述性比较，不能把当前行业当成当时主线题材。股本估算、未复权五日涨幅、当前可见证券目录及退市股票缺失均保留为限制。分笔样例只能佐证价格与成交量存在，不能提供个人委托顺序、交易所订单编号或真实成交回报。

## 选择与检验

有限网格包含 `3 × 2 × 4 × 3 × 3 × 2 × 3 = 1,296` 个组合。参数维度是买点、退出方式、D2 开盘涨幅、D1 换手率、D1 流通市值、D1 最低振幅及 D1 五日涨幅上限。具体区间以协议为准。

1. 按 D2 日期分为 1—6 月训练、7—8 月验证、9 月本次留出。D3 跨越阶段边界的样本从阶段评价中清除。
2. 训练阶段至少 100 次买入的规则才可进入候选，按 Wilson 95% 下限排序取前十名。
3. 前十名中验证阶段至少 30 次买入的规则才可选择，按验证阶段 Wilson 下限选出一个。
4. 先保存带协议及回放 SHA-256 的 `frozen-selection.json`，再计算 9 月表现。无合格规则则明确标记为探索性规则。
5. 同时报告按买入交易日聚类的 2,000 次 bootstrap 区间，减少把同日相关交易误当独立样本的影响。

网格搜索存在多重比较及选择偏差；上述区间不是多重检验修正后的“策略发现”证明。项目此前的研究使用过部分 2026 年日期，所以 9 月只能称为本次留出，不能称为从未查看过的未来数据。

## 运行

使用项目 Python 环境，先从 `banxia.limit_up_history` 导出 2026 年事件，并从 `banxia.limit_up_history_coverage` 导出实际市场交易日。输入文件为 `research/limit-up-t1-2026/postgres-snapshot.json`，结构为：

```json
{"events": ["数据库记录对象"], "coverage": ["覆盖记录对象"], "extracted_at": "提取时间"}
```

记录必须保留数值字段、日期、`raw.limit_rule_basis`、股本和行业依据。大体积 JSON 经终端导出可能被截断，先在数据库容器端 gzip，再在本地解压，并验证 JSON 和记录总数。

```bash
.venv/bin/python scripts/research_limit_up_t1.py collect
.venv/bin/python scripts/research_limit_up_t1.py replay
.venv/bin/python scripts/research_limit_up_t1.py select
.venv/bin/python scripts/research_limit_up_t1.py analyze
.venv/bin/python scripts/research_limit_up_t1.py evidence
.venv/bin/python scripts/render_t1_research.py
.venv/bin/python -m unittest discover -s tests -p test_t1_research.py -v
```

图表和 Excel 导出需在本地研究环境安装 `matplotlib` 与 `openpyxl`，生产运行时不依赖它们。`collect` 使用七个节点的持久连接，可恢复缓存并在失败后切换节点；失败项需补采后重新回放。`select` 不使用留出阶段结果；`analyze` 会拒绝读取与冻结时哈希不一致的回放或协议。

## 交付文件

原始行情及大表保存在 Git 忽略的 `research/limit-up-t1-2026/`：

| 文件 | 内容 |
| --- | --- |
| `postgres-snapshot.json`、`collection-manifest.json` | 原始事件、交易日、数据范围及哈希 |
| `daily/`、`minutes/`、`transactions/` | mootdx 原始日线、分时及抽样分笔 |
| `source-clock-audit.json.gz` | 分时分钟结束时间及首分钟集合竞价混量的核验材料 |
| `all-events.csv`、`replay.json.gz` | 所有事件 × 三种买点，包括失败和不可验证记录 |
| `winners.csv`、`达标股票明细.csv` | 两种可执行代理卖法中至少一种净收益超过 5% 的行；同一事件可能多买点重复 |
| `stock-summary.csv` | 按个股汇总的 early 买点及 target 退出基准 |
| `training-grid.csv`、`frozen-selection.json` | 全部训练试验及验证选择记录 |
| `selected-trades.csv` | 冻结规则筛中的所有事件，包括未成交和失败 |
| `feature-comparison.csv` | 训练与验证期内的价格、市值、换手及当前行业分组对比 |
| `transaction-evidence-examples.csv` | 9 个按月首次达标例与 3 个早期亏损例的分笔抽查 |
| `data-summary.json` | 报告、图表和表格的数据源 |
| `2026涨停隔日交易复盘.xlsx` | 中文股票清单、冻结规则全部样本、分笔例证和月度统计 |

报告、静态图表、Excel 和供审阅的 CSV／摘要副本纳入 Git，位于 `docs/assets/t1-2026/`；完整原始行情和全事件大表保留在本地研究目录。未来增加其他入场门槛、消息面、板块强度、资金分配或止损逻辑，都构成新规则，需要重新验证，不能继承本次历史达标率。
